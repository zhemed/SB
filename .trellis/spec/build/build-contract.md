# Build Contract & Release Artifact

`sb.sh` is **generated** by concatenating `src/*.sh` in a fixed order. The script is shipped as a
single file, so the concatenation must produce a self-contained program that runs standalone,
offline, and after being copied anywhere.

Source of truth: `scripts/build.sh`.

---

## 1. Never edit `sb.sh` directly

`sb.sh` carries a generated-artifact notice in its header. Every module repeats the same notice as
its first two lines.

```bash
# scripts/build.sh:13
readonly GENERATED_NOTICE="# Generated by scripts/build.sh from src/; do not edit sb.sh directly."
```

Editing `sb.sh` is always wrong. The correct loop is:

```bash
# after editing src/*.sh
bash scripts/build.sh          # regenerate sb.sh
bash scripts/build.sh --check  # verify sb.sh is in sync, without writing
bash tests/verify.sh           # full gate: build check, bash -n, pins, shellcheck, unit + repair
```

`tests/verify.sh:20` runs `build.sh --check` as its very first assertion, so a stale `sb.sh` fails
the whole suite immediately.

---

## 2. Module manifest — order and membership are enforced

The module list is a hardcoded array. `src/` must contain **exactly** these files, in **exactly**
this glob order.

```bash
# scripts/build.sh:17-29
readonly -a MODULES=(
  "00-bootstrap.sh"
  "10-acme.sh"
  ...
  "90-main.sh"
)
```

Enforcement: `scripts/build.sh:70-83` expands `"$SRC_DIR"/*.sh` under `nullglob`, requires the count
to match, and compares each glob entry against the manifest by name.

Consequences:

- Adding a module = add the file **and** insert it into `MODULES` in the same change.
- Renaming a module must keep the numeric prefix ordering consistent.
- Leaving a stray `.sh` file in `src/` breaks the build (`src module set does not match the build
  manifest`).
- Modules must be non-empty regular files, never symlinks (`scripts/build.sh:81`).

Numbering encodes concatenation order and roughly the install phase: `00-bootstrap` opens the
script, `90-main` closes it.

## 3. Module header contract

The first module is special: it carries the shebang and the artifact notices.

```bash
# src/00-bootstrap.sh:1-4
#!/bin/bash
# Generated by scripts/build.sh from src/; do not edit sb.sh directly.
# sb-generated-artifact: v1
# sb-module: 00-bootstrap
```

Every other module starts with **only** its module marker as line 1:

```bash
# src/20-ports.sh:1
# sb-module: 20-ports
```

Rules enforced by `scripts/build.sh:94-110`:

- The marker is exactly `# sb-module: ` + filename without `.sh`.
- The marker appears **exactly once** in the file, not merely as the first line.
- Only `00-bootstrap.sh` may carry the shebang / generated notice / artifact marker.

### Entry point marker

The last module must contain `# sb-entrypoint` exactly once; no other module may contain it.

```bash
# src/90-main.sh:173
# sb-entrypoint
```

Enforcement: `scripts/build.sh:111-116`, and again on the assembled candidate at
`scripts/build.sh:138-139`. Everything after the marker is the script body that actually runs:

```bash
# src/90-main.sh:209
prepare_runtime_state || exit 1
```

So "where does the program start?" is answered by the marker, not by grepping for a `main()`
function. Do not place executable top-level statements in any module before `90-main`.

## 4. Text hygiene (per module, build-fatal)

`scripts/build.sh:84-92` rejects, for **every** module:

| Check | Message |
|-------|---------|
| Valid UTF-8 (`iconv -f UTF-8 -t UTF-8`) | `is not valid UTF-8` |
| No UTF-8 BOM (first 3 bytes `ef bb bf`) | `contains a UTF-8 BOM` |
| No CR byte anywhere | `contains CR characters` |
| No NUL byte anywhere | `contains a NUL byte` |
| Final byte is LF | `must end with LF` |

These are the same rules `.editorconfig` declares (`charset = utf-8`, `end_of_line = lf`,
`insert_final_newline = true`). If your editor is misconfigured, the build — not the test suite —
will catch it.

Additionally `bash -n` runs on each module individually (`scripts/build.sh:117`) and on the
assembled artifact (`scripts/build.sh:157`).

## 5. Runtime self-containment rules

The concatenated script must not depend on project files at runtime.

- **No module loading.** `source` / `.` at the start of a line is rejected:
  `scripts/build.sh:148-149` → `runtime module loading is forbidden`.
- **No duplicate function definitions.** Because modules are concatenated into one namespace,
  `scripts/build.sh:151-153` extracts `name(){` definitions and fails on any duplicate. Two modules
  cannot each define a private helper with the same name.
- **No cross-module file reads.** The script never reads `src/`.

This is why copying a single `sb.sh` to a host, or running it through
`bash <(curl -Ls https://raw.githubusercontent.com/zhemed/SB/main/sb.sh)`, works.

---

## 6. Artifact generation is atomic

`scripts/build.sh:124-182` writes to a temporary candidate and only then publishes it:

- `--check` mode uses a candidate under `${TMPDIR:-/tmp}` and **never touches `sb.sh`**.
- Build mode uses `mktemp "$ROOT_DIR/.sb.sh.XXXXXX"` (same filesystem, so the final `mv` is atomic),
  then `chmod 755`.
- If the candidate is byte-identical to the current `sb.sh`, the candidate is deleted and the
  existing file — including its mtime — is left alone (`scripts/build.sh:176-182`).
- `.gitignore` covers `.sb.sh.*` so an interrupted build leaves no untracked noise.

Build mode prints the resulting digest; `--check` prints `build check passed: <sha256>`.

---

## 7. ACME reload hook is extracted and syntax-checked

The script embeds a heredoc-delimited reload hook (`ACMERELOAD`). The build asserts the terminator
appears exactly once and that the extracted body parses:

```bash
# scripts/build.sh:159-165
[[ $(grep -Fxc -- 'ACMERELOAD' "$candidate" || true) -eq 1 ]] ||
  fail "ACME reload heredoc terminator is invalid"
```

If you edit anything inside that heredoc, both the terminator count and the extraction assertions in
`tests/verify.sh:249-283` must keep passing. See `spec/runtime/certificates.md`.

---

## Common mistakes

- Editing `sb.sh` and committing it without touching `src/` — the next `build.sh` silently reverts
  your change. Always run `--check` before committing.
- Adding `src/05-something.sh` and forgetting `MODULES` — build fails with a set-mismatch message.
- Naming a helper identically in two modules — build fails with `duplicate function definitions`.
- Using `source` to share code between modules — build fails by design. Duplicate the helper or put
  it in `00-bootstrap.sh`.
