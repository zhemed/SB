# sing-box 版本与配置兼容性调查（仅研究，不实施）

## Goal

摸清我们钉死的内核 `1.10.7` 与当前稳定版 `1.14.0` / 开发版 `1.15` 之间的兼容性边界，
以及如果升级需要做什么。**纯调查，不含实施。**

## Requirements

- 用真实内核二进制验证，而非依据文档推断（文档已被证实在 `block` outbound 上与实现不符）。
- 覆盖服务端配置与客户端配置两条线。
- 明确 1.15 的优化范围，判断对我们是否有收益。
- 记录可复现的验证方法，供日后重启时直接使用。

## Acceptance Criteria

- [x] 服务端与客户端配置在 1.10.7 / 1.12 / 1.13 / 1.14 / 1.15α 上的实测结果
- [x] 服务端所需迁移映射（含实测通过的行为保全版配置）
- [x] 客户端配置的完整问题清单（含逐层剥离验证）
- [x] 1.15 变更范围与收益判定
- [x] 安全公告核查
- [x] 可复现的验证命令

## Outcome

**调查完成，结论写入 [research.md](./research.md)。**

核心结论：

1. 升级到 1.13+ 必须与配置迁移同时进行——两种配置形式互不兼容。
2. **客户端配置自 1.13.0（2026-02-28）起已不可用**，是独立的既存问题，与是否升级无关。
3. 1.15 唯一重头优化（TUN 自有 TCP/IP 栈）只作用于 TUN 接入路径，对我们服务端零收益。
4. 无未修复的安全公告。

## Decision

**一切等 1.15 稳定版发布后再决定**——含内核升级与客户端配置修复，本次均不实施。

判断标准已从「新版本有什么」改定为「当前有没有症状」（见 research.md §八）：

- 稳定运行、无内存增长/断流/吞吐异常 ⇒ 不必为 1.15 升级，继续停在 1.10.7 也是合理选择。
- 出现上述症状 ⇒ 升级信号，且收益来自 hysteria2 依赖的 QUIC 传输层（quic-go 跨 12 个版本），
  与接入方式（tproxy / TUN）无关。
- 若只想要传输层改进而不动配置 ⇒ 1.12.25 是实测能直接吃下现有配置的最后一个版本。

重启讨论时需先确认一个前提：客户端使用 tproxy 意味着未使用我们生成的 `sbox.json`
（那份是 TUN 模式），这决定 research.md §三 的客户端配置问题是否适用。
