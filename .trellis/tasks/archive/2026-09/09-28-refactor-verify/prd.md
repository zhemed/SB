# prd.md — 精简后的 A/B 回归验证

## Goal

用户当轮原话：「再检查一遍，总不能每次都让我提醒你吧」

上一轮把 19 处重复样板换成了三个共享帮手（`config_candidate`、`commit_config_candidate`、
`service_must_be_active`）。这类"等价替换"最容易出的问题是：**某一处的语义被悄悄改掉**
（重试改成返回、提示文案变化、清理路径变化、失败分支编号变化）。门禁只有 369 例，
覆盖不到全部 19 处，所以这轮做**逐流程 A/B 比对**。

## 做法

1. 取精简前版本 `git show HEAD~1:sb.sh` 与当前 `sb.sh`，用同一套抽取器得到函数集。
2. 同一沙箱里、同一组桩（systemctl / crontab / sing-box / 交互答案队列），对两边跑同一条流程：
   - 改 Hysteria2 端口（成功 / 冲突端口 / 取消）
   - 改 UUID（成功 / 与当前相同 / 格式错误 / 取消）
   - 改 SOCKS5 密码（成功 / 入口未启用 / 取消）
   - 启用 SOCKS5 入口（随机端口 / 自定义端口 / 取消 / 提交失败 / 回滚失败）
   - 停用 SOCKS5 入口（成功 / 取消 / 提交失败）
   - 设置上游（成功 / 提交失败 / 确认取消）与清除上游（成功 / 提交失败）
3. 每步比对四样东西：返回码、stdout（去除我本轮有意缩短的文案后）、`sb.json` 内容哈希、
   目录残留清单。
4. 差异必须逐条判定：**有意改动**（写入记录）或**回归**（修掉）。
5. 另跑：门禁、真实内核三项、卸载沙箱。

## 验收

- [ ] 比对脚本可复跑，结论表（流程 × 四样比对项）全绿或有明确判定
- [ ] 有差异的流程逐条给原因；是回归的修掉并补测试
- [ ] 门禁 / 真实内核三项 / 卸载沙箱 全绿
- [ ] 不复用上一轮的结论作证据——重新跑
