# implement.md — 精简后的 A/B 回归验证

## 做法

取精简前 `HEAD~1:sb.sh` 与当前工作树，各抽出全部函数体，放进同一套沙箱驱动器里跑**同一条流程**：
同一组桩（systemctl / crontab / sing-box / 交互答案队列 / 固定随机数与口令），
比对四样东西：**返回码、stdout（去掉本轮有意统一的文案后）、`sb.json` 内容、目录残留**。

流程 17 条：改 UUID（成功 / 与当前相同 / 格式错 / 取消）、改 SOCKS5 密码（成功 / 取消）、
启用 SOCKS5 入口（随机端口 / 自定义端口 / 取消 / 提交失败 / 回滚也失败）、停用入口（确认 / 取消 / 提交失败）、
设置上游（成功 / 取消）、清除上游（成功）。

## 结果：抓到两处真回归（都已修）

1. **[高] 帮手吞掉了 `commit_config` 的返回码**：`if commit_config …; then …; fi` 之后取 `$?` 恒为 0，
   于是"提交失败且自动回滚也失败"（返回 2）被误判成"可重试失败"，提示也变成
   "原配置未修改或已恢复"——与实际状态（回滚失败、备份仍在）不符。
   改成先执行再取码。已加门禁用例（`commit_config_candidate` 对返回 2 必须返回 2；
   失败可重试时返回 1、用户放弃返回 3）。
2. **[高] 候选路径传到了最后一个参数**：`config_candidate` 用 `"$@" "$tmp"` 调构造函数，
   而所有构造函数的第一个参数才是输出路径 → **启用/停用 SOCKS5 入口、设置/清除上游**
   四条菜单路径全部失效（jq 报 `--argjson` 非法，配置改不动）。
   改成 `"$builder" "$tmp" "${@:2}"`。已加门禁用例（构造函数必须拿到输出路径在第一位）。

修完后重跑：**17/17 全一致**（唯一差异是我本轮有意统一的失败文案，已在比对里映射）。

## 教训（写进记录，别再犯）

- 抽帮手时**返回码要单独接**（`cmd; status=$?`），不要用 `if cmd; then` 之后再取 `$?`。
- 帮手的**参数顺序约定**要有测试钉住，否则 19 处替换里错一处就是整条菜单路径失效。
- 对比脚本自己也要校验：本轮第一版 A/B 的 sed 规范化出错后静默产出空文件，
  让 17 条流程"全绿"——这是假绿。现在规范化用 python 并把出错当失败。
