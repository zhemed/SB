# research.md — SS-2022 vs SOCKS5：代价与路径

## 0. 先把"舒服"拆开

用户说的"舒服"可能指三件不同的事，价格完全不同：

| 想要的 | 真正的需求 | 是否必须公网 SOCKS5 |
|---|---|---|
| A 调试/手动用：`curl --socks5`、浏览器填代理、Telegram | 一个"什么程序都能填"的入口 | **不需要**（本机回环就够） |
| B 远端老客户端只认 SOCKS5 | 公网可用的 SOCKS5 | 需要 → 但这等于明文上公网 |
| C 嫌密钥/链接/客户端支持面麻烦 | 更省事 | 不需要（现状已经能一键复制链接） |

## 1. 两个形态的原文对比（本仓库证据）

v2.0.1 的第二个入站（`git show c9baa95^:src/30-server-config.sh`）：

```json
{ "type": "socks", "sniff": true, "sniff_override_destination": true,
  "tag": "socks5-sb", "listen": "::", "listen_port": <port_socks5>,
  "users": [{ "username": "sb", "password": "<随机口令>" }] }
```

v3.1.4 的（可选、默认不装）：

```json
{ "type": "shadowsocks", "tag": "ss-sb", "listen": "<listen>", "listen_port": <port_ss>,
  "network": "tcp", "method": "2022-blake3-aes-256-gcm", "password": "<44 位 base64>" }
```

## 2. 逐维度对比

| 维度 | SOCKS5（公网） | SS-2022（现状） |
|---|---|---|
| 传输加密 | **无**：口令与流量全程明文 | AEAD-2022 |
| 抗主动探测/重放 | 无；握手有固定字节特征 → **容易被指纹识别并封锁** | 有（EIH + 时间戳抗重放） |
| 客户端支持面 | 任何能填 SOCKS5 的程序（含 curl/浏览器/老固件） | 需要支持 2022 的客户端（mihomo/sing-box/Shadowrocket/Stash/Surge/Loon/Karing/v2rayN 都支持；**已归档的原版 Clash 不支持**） |
| 本机调试 | `curl --socks5-hostname`、浏览器直接填（本地 `curl --help` 确认支持 socks4/5） | curl/浏览器**不会** SS，需要一个客户端进程 |
| 时钟 | 不敏感 | 需要 NTP（两台机器已启用） |
| 凭据管理 | user/pass | 44 位 base64；不可推导，但写在配置里、修复会保留、启用后会显示 |
| 迁移成本 | 换回去 ≈ v3.0.0 的反向操作（入站+客户端产物+测试+规范一整轮） | 0（已经在跑） |

**关键一条**：SOCKS5 的代价不只是"明文"。它还是**可指纹识别**的——握手有固定特征，
正是"线路出问题时用来救急的那条腿"最不该有的性质。SS-2022 至少看起来像随机字节。

## 3. 三条路径与价格

### 路径 1（推荐）：保持 SS-2022，需要"手感"就加一个**仅回环的 SOCKS5**

- `listen: "127.0.0.1"` + 独立端口；**不进任何防火墙、公网零暴露**，与 hy2/SS 都不冲突。
- 服务器本机上 `curl --socks5-hostname 127.0.0.1:<port>`、浏览器、Telegram 直接可用；
  远端要用手动的话走 SSH 隧道（本机已配 SSH 复用，0.37s/次）。
- 价格：实现小—中（多一个可选入站 + 菜单【8】一个条目 + 测试）；不动现有入口，不影响客户端。
- 局限：只在服务器本机可达；手机这类远端设备想用要另外想办法。

### 路径 2：换回**公网** SOCKS5

- 价格最大：① 明文凭据+明文流量重新上公网（当初换掉它的唯一理由）；② 可被指纹识别；
  ③ 入站/客户端产物/测试/规范整轮重做（规模≈v3.0.0，我已做过一次，知道成本）。
- 唯一值得做的前提：**确实有某个必须用的客户端连不上 SS-2022**（要具体到是哪个、报什么错）。
- 注意：换回去并不会让"TCP 退路"更强；hy2 仍然是 UDP 主力，SS/SOCKS5 都只是第二条腿。

### 路径 3：两个入口并存（SS-2022 + 公网 SOCKS5）

- 表面上是"都要"，实质是路径 2 的安全代价照付，还多一个监听面与一套凭据要维护。**不推荐。**

## 4. 结论与推荐

- **推荐路径 1**：公网入口继续用 SS-2022（加密 + 抗指纹），本机手感用回环 SOCKS5 解决。
- 若"不舒服"的具体表现是"看不到链接/不知道怎么用"——v3.1.3 已经会直接打印链接与密钥，
  v3.1.4 又把每个提示的取消出口补齐了，这部分摩擦已经消掉，值得先体验一次再决定。
- **不推荐路径 2/3**，除非出现具体的客户端兼容故障。
