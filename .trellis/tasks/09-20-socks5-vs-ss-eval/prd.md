# 把可选入口从 SS-2022 换回 SOCKS5：评估

## Goal

用户感觉"SOCKS5 更舒服"。评估：把菜单【8】里那个**可选**入口从 Shadowsocks-2022
换回 SOCKS5（或换一种形态）值不值，以及"舒服"到底买的是什么。

**本任务只评估、不改代码**；结论与推荐见 [research.md](./research.md)。

## Requirements

- 分清"S舒服"的三种来源：调试/手动使用的便利、老客户端只认 SOCKS5、纯粹嫌 SS 麻烦。
- 逐维度对比：加密与可被识别性、客户端支持面、调试便利、时钟依赖、凭据管理、迁移成本。
- 给出可直接执行的三条路径与各自价格；明确指出**不推荐**的那条和原因。

## Acceptance Criteria

- [x] 两个入站形态的准确对比（含 v2.0.1 的 SOCKS5 模板原文与当前 SS 模板）
- [x] 安全维度不止"明文"，还包括"可被指纹识别"这一层
- [x] 三条路径的价格估算（含实现规模与是否触碰公网暴露面）
- [x] 明确推荐 + 需要用户确认的岔路口

## Notes

- 现状（v3.1.4）：入口可选、默认不装、TCP-only、AEAD-2022；启用后会显示分享链接与密钥。
- 本次评估不需要联网、不需要动任何机器——证据全部来自本仓库与本地工具输出。
