## 这轮抓到的真问题（都是我今天改出来的，属"修复本身的反向风险"）

1. **[高] 过滤器链只跑了第一级**（`src/60-cron.sh` `filter_crontab_checked`）
   - 我把多个过滤器当成"一条管道的多级"传给 `"$@"`，实际只有第一个执行，第二个被当成参数丢掉。
     后果：`remove_all_managed_crons` 删不掉每日重启任务 → 回读校验失败 → **卸载必然中止**
     （"服务已停止，但清理sb定时任务失败"），机器停在"服务已停、单元已删、配置还在"的半卸载状态。
   - 修法：改成逐级执行（每级读上一级输出，逐级检查退出码）。已加回归用例（两个过滤器都必须生效）。
2. **[高] 守卫分辨不出"过滤器崩了"与"正常删空"**（同一函数）
   - 只检查退出码 ≥2，而 `grep` 正常无匹配也是 1；过滤器中途失败（例如变量未绑定）会输出空结果，
     守卫放行 → 把用户的整份 crontab 写成空。
   - 修法：新增交叉校验——**凡是原来有、过滤后没了的行，都必须命中某个托管模式**，否则中止（返回 3）。
     已加两条用例（恶意过滤器删用户行 → 拒绝；崩掉的过滤器 → 拒绝）。
