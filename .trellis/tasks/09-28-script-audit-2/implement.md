# implement.md — 第二轮扫描（行为级 + 改动反审）

这轮换角度：审"今天这批修复本身"，并把风险流程真的跑起来（沙箱执行，不只读代码）。

## 一、改动反审与行为沙箱抓到的真问题（全部已修）

1. **[高] 主脚本调了只存在于生成物里的函数**：ACME 注册判据新增的指纹比对调用了
   `certificate_fingerprint`，它只定义在"续期 runner"的 heredoc 里 → 主脚本调用必 `command not found`。
   后果：申请 Cloudflare 证书必失败（证书已签发却被丢弃）、ACME 老用户每次启动自检失败、
   修复里"从 acme.sh 记录恢复证书"必失败并降级自签。已改为主脚本自带 `certificate_file_fingerprint`，
   并加门禁钉子：**只存在于 hook/runner heredoc 里的函数，不得在主脚本正文里被调用**
   （钉子的判定只认 `$(name …)` 与行首调用，验证过"注入真调用会红、仅在字符串里提到不红"）。
2. **[高] 取消证书更换会删掉正在生效的 ACME 状态**：返回码 3（取消）分支调了 `discard_acme_state`，
   它删的是当前证书本身 → 服务靠内存里的证书暂时不断，**下一次重启就起不来**；而屏幕还打印
   "已取消，未做任何修改"。已改成取消分支什么都不动，并加行为用例（取消时不许碰现场）。
3. **[高] 过滤器链只跑第一级**（`filter_crontab_checked`）：把多个过滤器当成一条管道的多级传 `"$@"`，
   第二个永不执行 → `remove_all_managed_crons` 删不掉每日重启行 → **卸载必然中止**在半卸载状态。
   已改成逐级执行，并加回归用例（两个过滤器都必须生效）。
4. **[高] 守卫分不清"过滤器崩了"与"正常删空"**：原先只看退出码 ≥2，而 grep 无匹配也是 1 →
   过滤器中途失败会把用户整份 crontab 写空。已改成交叉校验：被删掉的每一行都必须命中托管模式。
5. **[高] `commit_config` 的中断窗口**（行为沙箱实测）：配置 `mv` 之后、收尾之前被 Ctrl-C，
   改动已生效且服务已重启，但脚本一声不吭、节点文件还是旧端口，还留下 `.sb.json.backup.*`。
   已在该窗口屏蔽 INT/TERM/HUP，收尾完成后恢复中断处理。
6. **[高] 修复中断留下的备份永不清理**（行为沙箱实测：一次开头 Ctrl-C 留一份 ~30MB 内核拷贝，
   后续成功修复也不清）。已让 abort 在 `not_needed` / `target_restored` 分支同样删除修复前备份，
   并在清理流程里按规则清陈旧副本。
7. **[中] 陈旧备份累积**：`.sb.json.before-repair.*`（每次修复一个，会被当成恢复候选）、
   `.sb.json.backup.*`（崩溃残留）。已纳入清理：前者只保留最近 2 份，后者在修复清理时删除
   （不动当前正在用的那一份）。
8. **[中] SOCKS5 入站被改坏会让整个客户�端产物生成失败**（我上一轮改的）：已区分"入站不存在"
   与"入站坏掉"——后者保留旧的 socks5.txt、只跳过该入口，Hysteria2 节点照常生成。
9. **[低] 一批小修**：`changeuuid` 输入与当前相同的 UUID 不再白重启一次；可选功能菜单区分
   "未配置"与"状态文件损坏"；`save_relay_settings` 同步内存全局量（回滚不再用陈旧值）；
   `commit_config` 回滚文案区分"配置已回滚、服务未起来"与"回滚失败"；删掉我误留的重复 `readp`。
