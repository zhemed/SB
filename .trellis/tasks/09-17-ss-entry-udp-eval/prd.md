# SS-2022 入口是否承载 UDP：评估与结论（不实施）

## Goal

用户提问：可选的 Shadowsocks-2022 入口现在是 TCP-only，**换成/加上 UDP 有什么代价**？
本任务只回答这个问题并留下结论，**不改代码**。

## Requirements

- 结论必须基于真实内核实测，而不是文档推断。
- 代价要逐条落到这个仓库的具体位置（端口、路由规则、客户端模板、规范与测试）。
- 记录被否决的替代方案与**重新评估的触发条件**，避免以后重新吵一遍。

## Acceptance Criteria

- [x] 实测：SS 入站的 `network` 取值与 UDP 端口冲突的真实行为
- [x] 代价清单（含"它解决不了什么"）
- [x] 替代方案（udp_over_tcp / 独立 UDP 端口）与各自价格
- [x] 明确结论与重新评估的触发条件

## Decision

**不实施。维持 TCP-only。** 理由与证据见 [research.md](./research.md)。

重新评估的触发条件（任一成立再谈）：
1. 实测到 **QUIC 被定点识别/干扰而裸 UDP 可用**（这是我们目前唯一没有覆盖的故障形态）；
2. 且确实需要服务**非 QUIC 的 UDP**（游戏、语音、DNS）——因为我们的路由规则会拦 QUIC/STUN；
3. 且接受"多一个 UDP 端口"或"改动 hy2 端口导致客户端重导"的代价。

## Notes

- 本任务为决策记录，**刻意不产生任何代码改动**。
- 现状（v3.1.4）：SS-2022 入口可选、默认不装、`network: "tcp"`，UDP 由 hysteria2 承担。
