# prd.md — 脚本本体审计

## Goal

用户指令原话：「你连个脚本都不认真，你还去关注其它的？自己去扫一遍脚本去，天天正事不干，瞎搞什么」

只扫**仓库里的脚本本体**：`src/` 十一个模块、由它生成的 `sb.sh`、以及 `tests/`。
不看仓库以外的东西，不碰用户文档措辞，不做无关动作。

## 要抓的问题类型（按严重度）

1. **会破坏机器的**：改坏配置、丢凭据、服务起不来、半提交状态、回滚不完整。
2. **静默失败**：该报错却被 `|| true` 吞掉、返回码丢失、失败后仍打印"成功"。
3. **数据与参数**：未校验输入直写配置、jq 选择器过宽或过窄、端口/凭据边界。
4. **状态不一致**：菜单显示与实际不符、返回提示指向错的菜单、编号与选项不符。
5. **死代码 / 不可达**：定义了没调用的函数、永远为真的分支、赋值后从未使用的变量。
6. **可移植性**：未绑定变量、命令替换吃换行、locale 相关比较。

## 做法

- 逐模块读一遍（不是只看 diff），重点是有外部副作用的部分：配置渲染、提交与回滚、
  状态文件读写、证书交接、定时任务、卸载。
- 已在门禁里的检查（shellcheck 0.10.0、unit、repair）算基线，不重复报它已覆盖的。
- 每条发现必须写清：文件:行、为什么是问题、怎么复现或推理、准备怎么修。
- 只修确认的；不确定的列出来给用户，不"顺手改"。

## Acceptance Criteria

- [ ] 十一个模块 + tests 至少各读一遍，产出发现清单（含"没问题"的结论）
- [ ] 确认的缺陷逐条修掉，带测试或门禁钉子
- [ ] 门禁全绿（unit / repair / verify + shellcheck）
- [ ] 报告只给清单与结论，不铺陈
- [ ] 只动仓库内的脚本与测试；README/规范除非事实错误否则不碰
