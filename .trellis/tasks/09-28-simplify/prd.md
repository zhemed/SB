# prd.md — 精简一轮（去重复、删死码、缩文案）

## Goal

用户当轮原话：「你看看吧，该精简精简，该修的修，你老是不认真」

脚本经过多轮加固后积累了冗余。这一轮在**不改变行为、不降低安全性**的前提下做减法，
并顺手修掉过程中发现的真缺陷。

## 精简对象（按收益排序）

1. **零调用函数 / 死常量 / 死分支**：定义了没人用，或永远走不到。
2. **重复样板**：`70-management.sh` 里八处"建候选 → jq 改写 → chmod → commit_config →
   成功/失败回滚"几乎逐字重复；`85-repair.sh` / `10-acme.sh` 里也有同类块。
3. **冗余校验**：同一件事校验两遍（例如候选写完又校验、入口存在性三处判定口径不一）。
4. **冗长文案**：用户已多次要求去掉多余解释；统一并收短用户可见的长句。
5. **过厚防御**：重复的可达性检查、同一条件的多层 if。

## 不做

- 不改交互流程与选项编号；不改对外行为；不降级任何安全检查（属主/权限/符号链接/回滚/锁）。
- 不动用户文档（README）与规范措辞，除非事实错误。

## 验收

- [ ] 门禁 `tests/verify.sh` 全绿；真实内核三项（hy2-only 启动、客户端产物、两跳中转）通过
- [ ] 精简量可度量：行数与函数数目的变化、删掉的重复块数量
- [ ] 行为不变的证据：关键流程沙箱复跑（卸载、SOCKS5 入口、上游设置/清除、修复中断清理）
- [ ] 顺手修掉的缺陷单独列出
